# 수업 전체 리허설 2회와 개선 결과

대상: 이 버스는 누구를 지나치는가 · 고등학교 통합사회 · 2인 1조

배포: https://temporary-prompt-poplar-ezg5yq8.vercel.app/

## 판정

주민 자료 확인 → 첫 설계 → 운행 → 놓친 주민 검토 → 재설계 → 비교 → 성찰 → 교사 확인 → 종료의 핵심 흐름은 수업에 사용할 수 있는 수준이다. 두 개의 실제 Firebase 수업에서 각각 두 차례 운행을 완료했다. 첫 리허설에서 발견한 안내·표시 문제를 고치고, 두 번째 리허설에서 배포본으로 확인했다.

이는 사람이 참여한 두 차시 수업 실험이 아니라, 에이전트가 교사·학생 탭을 조작한 기능 리허설이다. 45분의 각 단계를 순서대로 통과하되 대기 시간을 단축하고 버스 애니메이션은 10배속으로 실행했다. 화면은 아이패드 11인치 가로 기준 1194×834로 점검했다. 동일 브라우저의 별도 탭이므로 독립된 실물 기기·Safari·교실 무선망·여러 모둠 동시 부하까지 검증한 것은 아니다.

|---|---|---|

| 긴 노선을 만들면 왕복 시간이 편집 패널 아래로 밀린다. | 왕복 시간·다음 출발·운행 규칙을 노선 목록 위로 옮겼다. | 7개 정류장 노선에서 ‘왕복 158분 · 다음 출발 10:00 이후’를 바로 확인했다. |
| 10:00 자동 종료 직후 시도 기록 버튼의 횟수가 이전 값으로 남는다. | 전체 화면을 다시 그리지 않고 완료 시점에 횟수를 갱신한다. | 결과 버튼을 누르기 전 ‘시도 기록 2’가 표시됐다. |
| 성찰에서 자동 저장 범위가 모호하고 파일 내보내기가 제출처럼 보인다. | 작성 진행 0/3~3/3과 자동 전달 안내를 표시하고, ‘작성 마치기’와 선택적인 파일 다운로드를 분리했다. | 3/3 표시와 교사 수신, 양쪽 새로고침 후 답변 복원을 확인했다. |
| 긴 결과·성찰 화면에서 제목과 닫기 버튼을 잃기 쉽다. | 모달 제목을 상단에 고정하고 결과 경로의 글자 크기·대비를 높였다. | 성찰 하단에서도 제목·닫기와 하단 행동 버튼이 보였다. |

## 교사 입장에서 본 피드백과 반영

| 발견한 문제 | 반영한 개선 | 두 번째 확인 |
|---|---|---|
| 일시정지 화면에 이전 활동의 지시가 그대로 표시된다. | 대기·일시정지·종료에 맞는 전용 안내로 바꿨다. | 운행을 멈추면 학생에게 모둠 대화를 안내하고, 재개하면 운행이 이어졌다. |
| 자동 운행이 끝났는데 대시보드에는 ‘운행 중’으로 보인다. | 10:00 완료를 결과 확인 상태로 보고한다. | 학생이 결과 모달을 열기 전 교사 화면에 ‘결과 비교 · 2회’가 표시됐다. |
| 종료 버튼을 누르면 작성 현황을 확인할 기회 없이 잠긴다. | 종료 전 재설계 수신·성찰 완료 모둠 수와 미완료 안내를 보여 준다. | 0/1 상태에서 취소해 활동을 이어갔고, 1/1 수신 후 종료했다. |
| 결과 내보내기 함수는 있으나 화면에서 접근하기 어렵다. | 모둠 현황 카드에 ‘결과 내려받기’를 추가했다. 삭제 요청한 도구 사이드바는 복구하지 않았다. | 버튼 클릭 시 콘솔 오류는 없었으나 앱 내 브라우저에서 다운로드 완료 이벤트를 받지 못했다. 실제 파일 저장 완료는 미확인이다. |

## 리허설 1 — 개선 전 진단

수업 992900, 모둠 ‘리허설 1 · 두 사람’. 모든 단계, 두 운행, 성찰 세 문항, 교사 수신, 새로고침 복원, 종료까지 진행했다.

첫 설계: 1호차 아파트→마을 버스터미널→공장, 07:15, 저상. 2호차 언덕마을→다리 북단→학교→병원→마을 버스터미널, 07:30.

수정 설계: 같은 노선에서 2호차를 07:32 출발 저상버스로 변경.

| 결과 | 첫 설계 | 수정 설계 |
|---|---:|---:|
| 정시 도착 | 5명 | 4명 |
| 지각 | 2명 | 2명 |
| 이동 불가 | 1명 | 2명 |
| 이동 가능한 주민 평균 | 54분 / 7명 | 59분 / 6명 |

지영은 이동 불가에서 08:09 병원 도착으로 바뀌었다. 저상 배치가 바뀌며 하늘·건우는 이동 불가가 되었고, 민서·복례·도현·은서는 2분씩 더 걸렸다. 실제 계산에서 발생한 변화이며 도덕 점수나 임의의 불이익을 부여하지 않았다.

## 리허설 2 — 개선 후 배포본

수업 962436, 모둠 ‘리허설 2 · 두 사람’.

1. 교사가 수업을 만들고 QR·접속 주소·수업 코드를 확인했다. 학생은 세션 주소로 들어와 모둠 이름을 입력했다. QR을 실제 카메라로 스캔하지는 않았다.
2. 학생 목적 안내와 조작 안내를 확인하고, 교사가 주민 확인 단계를 시작했다. 별도 인쇄 자료 화면에 주민 8명의 출발·도착·보행·저상 조건이 존재함을 확인했다. 물리 인쇄는 하지 않았다.
3. 첫 설계에서 지도 클릭으로 정류장을 추가하고 운행 기본 설정에서 출발 시각을 바꿨다.
4. 첫 운행 도중 교사가 일시정지·재개했다. 10:00까지 애니메이션이 끝나고 첫 결과를 확인했다.
5. 주민 검토 단계에서 민서의 실제 환승 경로와 지각 사유를 열었다.
6. 재설계 단계에서 1호차 정류장을 삭제하고, 2호차에는 중간 삽입과 끝 추가를 사용했다. 2호차 출발 시각과 저상 배치를 바꾸고 다시 10:00까지 운행했다.
7. 전후 비교에서 8명 모두의 변화를 확인했다. 자동 완료 직후 학생 시도 횟수와 교사 결과 상태가 맞았다.
8. 개념 정리에서 세 답변을 작성했다. 교사가 3/3 수신한 뒤 양쪽을 새로고침하여 두 시도·세 답변을 복원했다.
9. 종료 전 미완료 상태의 확인 창을 취소하는 흐름과, 완료 후 종료하여 학생 편집이 잠기는 흐름을 확인했다.

첫 설계: 1호차 아파트→마을 버스터미널→공장→학교→병원, 07:20, 저상. 2호차 언덕마을→다리 북단→병원, 07:30.

수정 설계: 1호차 아파트→마을 버스터미널→공장, 07:20. 2호차 언덕마을→다리 북단→학교→병원→아파트→마을 버스터미널→공장, 07:32, 저상.

| 주민 | 첫 도착 | 수정 도착 | 변화 |
|---|---|---|---|
| 민서 | 08:26, 지각 | 07:58, 정시 | 28분 단축 |
| 준호 | 07:41, 정시 | 07:41, 정시 | 동일 |
| 지영 | 이동 불가 | 08:09, 정시 | 새롭게 이동 가능 |
| 복례 | 08:04, 정시 | 08:11, 정시 | 7분 증가 |
| 도현 | 08:04, 정시 | 09:48, 지각 | 104분 증가 |
| 은서 | 08:13, 지각 | 09:37, 지각 | 84분 증가 |
| 하늘 | 09:19, 지각 | 08:44, 지각 | 35분 단축 |
| 건우 | 09:28, 지각 | 08:53, 지각 | 35분 단축 |

정시/지각/불가는 3/4/1명에서 4/4/0명으로 변했다. 평균은 이동 가능한 7명 68분에서 8명 77분으로 변했다. 제외 인원도 함께 표시되어 ‘이동 불가를 평균에서 빼면 좋아 보이는’ 오해를 줄인다.

### 시간 계산을 따라간 사례

민서의 첫 설계: 07:20 집 출발 → 4분 보행 → 07:24 언덕마을 정류장 → 6분 대기 → 07:30 2호차 → 07:57 병원 하차 → 환승 이동 2분을 포함해 16분 대기·이동 → 08:13 1호차 → 08:22 학교 하차 → 4분 보행 → 08:26 도착. 총 4+6+27+16+9+4=66분, 08:20 시한보다 6분 늦다.

## 자동 검사와 남은 범위

- `node tests/engine.test.mjs`: 18개 운행 계산 검사 통과. 왕복·정차·회차, 출발 뒤 탑승 금지, 2분 환승, 저상 조건, 모든 56개 정류장 쌍의 연속 경로, 시간표와 애니메이션의 일관성 포함.
- `node tests/classroom.test.mjs`: 완료 결과만 교사에 보고, 저장 직렬화·중복 방지·재시도, 교사 정지·재개, 완료 횟수 갱신·복원, 1,260개 노선 삽입 문맥, 되돌리기, 이전 조건 기록 보존 통과.
- 배포본 `app.js`, `main.js`, `product.css`가 로컬 수정본과 일치함을 확인했다.
- 미확인: 실제 iPad Safari 터치·키보드, 카메라 QR 스캔, 물리 인쇄, 여러 기기의 동시 접속 부하, 교실 Wi-Fi 단절·복구, 결과 파일이 사용자 기기에 최종 저장되는 과정.
- 교사 권한은 기존과 같이 수업을 만든 기기·브라우저에 의존한다. 공유할 교사는 자기 기기에서 새 수업을 생성하고, 주민 자료를 미리 배부하는 방식이 적절하다.
