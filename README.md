# 이 버스는 누구를 지나치는가

고등학교 통합사회 45분 수업에서 모둠당 기기 한 대로 진행하는 노선 설계 웹앱입니다. 주민 12명과 정류장 8개, 버스 두 대(저상버스 한 대)의 가상 아침을 계산합니다.

## 실행

프로젝트 폴더에서 `node serve.mjs`를 실행한 뒤 http://localhost:5173 에 접속합니다. Node.js 외의 설치나 API 키는 필요하지 않습니다. `dist` 폴더는 일반 정적 웹 서버에서도 그대로 실행할 수 있습니다.

앱 자체에는 로그인이나 서버 데이터베이스가 없습니다. 같은 네트워크의 다른 기기에서는 서버를 실행하는 컴퓨터의 내부 IP와 5173 포트로 접속할 수 있습니다. 학교 네트워크와 방화벽 정책에 따라 기기 간 접속이 제한될 수 있으며, 실제 교실 네트워크 접속은 이번 검증 범위에 포함되지 않았습니다.

## 사용 방법

1. 오른쪽 주민을 눌러 집, 목적지, 출발 가능 시각, 도착 시한, 보행·저상버스 조건을 확인합니다.
2. 지도 위 1호차 또는 2호차를 고르고 정류장을 차례로 누릅니다. 기존 정류장을 노선 끝에 추가합니다.
3. 아래 목록의 ×로 삭제합니다. 이름을 누른 뒤 앞으로·뒤로 버튼으로 순서를 바꾸거나, 카드를 끌어 옮깁니다. 되돌리기는 설계 변경 40회까지 지원합니다.
4. 버스별 첫 출발 시각과 저상버스 배치를 정합니다. 주민별 예상 결과와 왕복 시간이 즉시 바뀝니다.
5. ‘운행해 보기’로 시작합니다. 일시정지, 1×·3×·10× 보기, 시간 막대로 각 장면을 살펴봅니다. ‘결과 확인하기’는 10:00의 계산 결과를 보여 주고 시도를 저장합니다.
6. 다시 설계하고 운행한 뒤 첫 시도와 비교합니다. 기록의 주민 이름을 누르면 그 시도의 상세 경로를 봅니다.
7. 세 질문에 모둠 생각을 적습니다. 답변과 현재 설계·이전 시도는 같은 브라우저에 자동 저장됩니다. ‘기록 내보내기’는 JSON 파일로 결과와 답변을 보관합니다.

다른 기기·브라우저와 기록이 동기화되지 않습니다. 브라우저 데이터 삭제 시 기록도 삭제되므로 필요한 기록은 내보내세요.

## 수업 흐름

주민 상황 5분 → 첫 설계 8분 → 운행·결과 5분 → 놓친 주민 7분 → 재설계 8분 → 전후 비교 5분 → 개념 정리 7분.

개념 설명은 결과를 본 뒤 진행합니다. 공간 불평등, 실질적인 기회, 공공서비스 분배를 주민의 이름과 구체적인 시간 변화에 연결합니다. 도덕 점수나 정답 노선을 두지 않습니다.

## 자료와 계산 수정

- `dist/data.js`: 주민 조건, 시각, 보행 접근로, 도로 연결·구간 시간, 정류장 좌표, 기본 설계와 수업 순서. 모두 교육용 가상 자료입니다.
- `dist/engine.js`: 최단 도로 경로, 실제 왕복 시간표, 주민의 최대 1회 환승 경로, 상태 판정과 애니메이션 좌표.
- `dist/app.js`: 노선 편집, 주민 패널, 운행 재생, 시도 비교, 성찰, 기기별 저장.
- `dist/style.css`: 지도·패널 비율, 화면 크기별 편집 배치.
- `dist/assets`: 새로 생성한 지도 배경과 주민 그림. 노선·정류장·차량·버튼은 별도 화면 요소입니다.
- `artwork-generated/prompts.txt`: 내장 이미지 생성 도구에 사용한 최종 프롬프트. 참고 화면을 통째로 배경에 사용하지 않았습니다.

시각은 자정부터의 분입니다(07:00=420). `access`, `egress`는 주민이 이용 가능한 접근로와 보행 시간이며, 각 이동 구간은 `maxWalk` 이하여야 합니다. 현재 예시 주민은 모두 대중교통 이용 경로가 필요합니다. 각 주민은 출발 가능한 가장 이른 시각에 집에서 출발합니다.

주민 조건을 바꾸어 새 수업을 만들 때는 `SCENARIO.id`와 `app.js`의 저장 키 `KEY`를 함께 변경해 서로 다른 도시 조건의 기록을 섞지 마세요.

## 운행 약속

- 두 정류장 사이에는 연결된 도로 중 시간이 가장 짧은 길을 사용합니다. 노선 목록에 있는 정류장에서만 승하차합니다.
- 중간 정류장 정차 1분, 각 종점 정차 1분 + 회차 2분입니다. 첫 출발은 기점에서 떠나는 시각입니다.
- 왕복 시간은 도로 이동의 두 배 + 중간 정차의 두 배 + 양쪽 종점 6분입니다. 다음 출발은 이 실제 왕복 시간으로 정해집니다.
- 이미 떠난 버스에는 탑승할 수 없습니다. 출발과 정확히 같은 시각에 정류장에 도착하면 탑승 가능합니다.
- 환승은 같은 정류장에서 2분 이상, 다른 버스로 최대 한 번입니다. 저상버스가 필요한 주민은 모든 탑승 구간에서 저상버스를 이용해야 합니다.
- 조건에 맞는 가장 이른 목적지 도착을 선택합니다. 시한과 같은 시각이면 정시, 시한 이후 10:00까지면 지각입니다. 하차 후 이동까지 포함해 10:00까지 갈 수 없으면 이동 불가입니다.
- 평균은 집에서 출발한 뒤의 전체 이동 시간이며 대기를 포함합니다. 이동 가능한 주민 수와 평균에서 제외한 이동 불가 인원을 함께 표시합니다.
- 혼잡·정원 제한, 교통 체증, 무작위 사건은 생략합니다. 지도 속 주차 차량은 배경이며 운행 차량은 화면의 1·2호차 두 대입니다.

## 검증

`node tests/engine.test.mjs` — 13개 계산 검증을 통과했습니다. 시간표 연속성, 도로 좌표, 한 대의 물리적 왕복, 이미 출발한 버스, 환승 2분 경계, 저상 제한, 10:00 경계, 설계 변경에 따른 결과 변화와 애니메이션 위치를 검사합니다.

브라우저에서 정류장 추가·삭제·클릭 순서 변경·실제 드래그·되돌리기·첫 출발 변경·저상 배치 변경·운행·일시정지·빠른 보기·시각 탐색·첫 결과 저장·재설계·전후 비교·성찰 작성·새로고침 복구를 직접 확인했습니다.

1586×992 화면을 참고 이미지와 비교했습니다. 1366×768 노트북, 1024×768 아이패드 가로 크기에서 8개 정류장과 편집·실행 버튼의 가림 및 화면 경계를 검사하고 패널을 보완했습니다. 실제 iPad 하드웨어/Safari, 학교 Wi-Fi, 다중 기기 접속은 검증하지 않았습니다. 터치 전용 핵심 조작은 클릭 기반으로 제공하며 마우스와 포인터 드래그를 지원합니다.

WebMCP 설계 읽기·설계 변경 도구의 등록, 유효 입력, 중복 정류장 거부와 상태 보존을 지원 브라우저에서 확인했습니다.

### 예시: 초기 설계에서 준호

07:10 집 출발 → 환승센터까지 도보 15분 → 07:25 정류장 도착 → 대기 5분 → 07:30 2호차 탑승 → 다리 남단 정차 포함 버스 16분 → 07:46 공장 정류장 하차 → 작업장까지 4분 → **07:50 도착**. 총 40분이며 08:00 교대에 정시 도착합니다. 브라우저에서 07:35 탑승 상태와 07:50 도착 상태를 확인했습니다.

### 비교 검증 사례

1호차를 아파트 → 환승센터 → 다리 북단 → 언덕마을 → 학교 → 병원, 첫 출발 07:30으로 바꾼 예시에서 왕복은 58분에서 156분으로 늘었습니다. 지영·복례·은서·만수는 새로 이동할 수 있게 되었고, 민서·도현은 29분 더 걸렸습니다. 하늘·태식·수진은 운행 범위 안에 도착하는 연결편을 놓쳤습니다. 결과는 시간표에서 계산되며 이 예시를 정답으로 권하지 않습니다.
