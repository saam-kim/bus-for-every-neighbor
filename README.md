# 이 버스는 누구를 지나치는가

고등학교 통합사회 45분 수업에서 모둠당 기기 한 대로 진행하는 노선 설계 웹앱입니다. 주민 8명과 정류장 8개, 버스 두 대(저상버스 한 대)의 가상 아침을 계산합니다.

## 실행

프로젝트 폴더에서 `node serve.mjs`를 실행한 뒤 http://localhost:5173 에 접속합니다. `dist` 폴더는 일반 정적 웹 서버에서도 그대로 실행할 수 있습니다.

`dist/firebase-config.js`에 Firebase 웹 앱 설정이 있으면 익명 인증과 Realtime Database를 사용해 교사·학생 기기를 연결합니다. 설정이 `null`인 개발 상태에서는 같은 브라우저의 탭끼리만 동작하는 시연용 저장소로 자동 전환됩니다. 실제 수업에서는 Firebase 설정을 사용하세요.

## 사용 방법

1. 첫 화면에서 교사가 **새 수업 만들기**를 누르면 6자리 수업 코드와 학생 입장 QR이 만들어집니다.
2. 학생은 QR을 찍거나 QR 창의 접속 주소(#join)에서 6자리 코드를 입력하고 모둠 이름으로 입장합니다. 학생 계정은 필요하지 않습니다.
3. 교사는 7단계 수업 막대와 타이머로 진행하고, 전체 일시정지·안내 문구·단계 이동을 학생 화면에 보냅니다.
4. 교사 대시보드의 **자료 인쇄하기**로 A4 한쪽 주민 조건표를 나눠 줍니다. 학생은 인쇄 자료를 보며 지도에서 버스와 정류장을 골라 노선·첫 출발·저상버스를 설계합니다. 기존 정류장을 선택한 뒤 새 정류장을 누르면 선택한 위치 바로 뒤에 들어갑니다. 계속 누르면 방금 추가한 정류장 뒤로 이어지고, ‘맨 끝에 추가하기’로 끝에서 연결할 수 있습니다.
5. ‘운행해 보기’에서 일시정지, 1×·3×·10× 보기, 시간 막대로 장면을 살펴보고 결과 확인 또는 상단 비교·정리를 누르면 결과가 저장됩니다. 10:00까지 재생한 경우에도 자동 저장됩니다.
6. 교사 화면에는 모둠별 현재 화면, 시도 수, 정시·지각·이동 불가 수, 성찰 진행과 자주 놓친 주민이 실시간으로 나타납니다.
7. 학생은 다시 설계한 결과를 첫 시도와 비교하고 세 질문에 답합니다. 교사는 모둠 상세에서 첫 시도와 최근 시도의 주민별 변화, 세 질문에 쓴 답변을 확인합니다. 학생은 결과 화면에서 모둠 기록을 JSON으로 내보낼 수 있습니다.

학생 기기에는 현재 설계와 시도 기록이 함께 저장되어 새로고침 뒤 복구됩니다. 브라우저 데이터를 지우면 기기 저장본은 삭제되므로 필요한 기록은 학생 결과 화면에서 내보내세요.

## Firebase 설정

1. Firebase 프로젝트에 웹 앱을 등록하고 `dist/firebase-config.js`의 `firebaseConfig`에 발급된 설정 객체를 넣습니다.
2. Authentication에서 익명 로그인을 사용 설정합니다.
3. Realtime Database를 만든 뒤 `firebase/database.rules.json`을 규칙으로 배포합니다.
4. 배포 주소를 Authentication의 승인된 도메인에 추가합니다.

수업 데이터는 `classes/{6자리 코드}` 아래에 저장됩니다. 수업을 만든 익명 사용자만 단계·타이머·전체 수업을 변경할 수 있고, 학생 기기는 자기 모둠 기록만 수정할 수 있도록 규칙을 분리했습니다. 모둠 이름에는 학생 실명을 적지 않는 운영을 권장합니다.

## 수업 흐름

주민 상황 5분 → 첫 설계 8분 → 운행·결과 5분 → 놓친 주민 7분 → 재설계 8분 → 전후 비교 5분 → 개념 정리 7분.

개념 설명은 결과를 본 뒤 진행합니다. 공간 불평등, 실질적인 기회, 공공서비스 분배를 주민의 이름과 구체적인 시간 변화에 연결합니다. 도덕 점수나 정답 노선을 두지 않습니다.

## 자료와 계산 수정

- `dist/data.js`: 주민 조건, 시각, 보행 접근로, 도로 연결·구간 시간, 정류장 좌표, 기본 설계와 수업 순서. 모두 교육용 가상 자료입니다.
- `dist/engine.js`: 최단 도로 경로, 실제 왕복 시간표, 주민의 최대 1회 환승 경로, 상태 판정과 애니메이션 좌표.
- `dist/app.js`: 노선 편집, 주민 패널, 운행 재생, 시도 비교, 성찰, 기기별 저장.
- `dist/main.js`: 교사·학생 입장, QR, 7단계 수업 대시보드와 실시간 집계.
- `dist/classroom-sync.js`: 완료한 시도만 집계하고 동일한 저장 요청을 합치는 순차 동기화.
- `dist/classroom.js`: Firebase 익명 인증·Realtime Database 연결과 로컬 시연용 대체 저장소.
- `dist/classroom.css`: 입장 화면, 교사 대시보드, 수업 상태 표시와 반응형 배치.
- `firebase/database.rules.json`: 교사와 각 학생 모둠의 쓰기 범위를 제한하는 데이터베이스 규칙.
- `dist/style.css`: 지도·패널 비율, 화면 크기별 편집 배치.
- `dist/assets`: 새로 생성한 지도 배경과 주민 그림. 노선·정류장·차량·버튼은 별도 화면 요소입니다.
- `artwork-generated/prompts.txt`: 내장 이미지 생성 도구에 사용한 최종 프롬프트. 참고 화면을 통째로 배경에 사용하지 않았습니다.

시각은 자정부터의 분입니다(07:00=420). `access`, `egress`는 주민이 이용 가능한 접근로와 보행 시간이며, 각 이동 구간은 `maxWalk` 이하여야 합니다. 현재 예시 주민은 모두 대중교통 이용 경로가 필요합니다. 각 주민은 출발 가능한 가장 이른 시각에 집에서 출발합니다.

주민 조건을 바꾸어 새 수업을 만들 때는 `SCENARIO.id`와 `app.js`의 저장 키 `KEY`를 함께 변경해 서로 다른 도시 조건의 기록을 섞지 마세요.

## 운행 약속

- 두 정류장 사이에는 연결된 도로 중 시간이 가장 짧은 길을 사용합니다. 노선 목록에 있는 정류장에서만 승하차합니다.
- 중간 정류장 정차 1분, 각 종점 정차 1분 + 회차 2분입니다. 첫 출발은 기점에서 떠나는 시각입니다.
- 왕복 시간은 도로 이동의 두 배 + 중간 정차의 두 배 + 양쪽 종점 6분입니다. 다음 출발은 이 실제 왕복 시간으로 정해집니다.
- 이미 떠난 버스에는 탑승할 수 없습니다. 출발과 정확히 같은 시각에 정류장에 도착하면 탑승 가능합니다.
- 환승은 같은 정류장에서 2분 이상, 다른 버스로 최대 한 번입니다. 저상버스가 필요한 주민은 모든 탑승 구간에서 저상버스를 이용해야 합니다.
- 조건에 맞는 가장 이른 목적지 도착을 선택합니다. 시한과 같은 시각이면 정시, 시한 이후 10:00까지면 지각입니다. 하차 후 이동까지 포함해 10:00까지 갈 수 없으면 이동 불가입니다.
- 평균은 집에서 출발한 뒤의 전체 이동 시간이며 대기를 포함합니다. 이동 가능한 주민 수와 평균에서 제외한 이동 불가 인원을 함께 표시합니다.
- 혼잡·정원 제한, 교통 체증, 무작위 사건은 생략합니다. 지도 속 주차 차량은 배경이며 운행 차량은 화면의 1·2호차 두 대입니다.

## 검증

`node tests/classroom.test.mjs` — 완료 결과 집계, 중복 전송 방지, 순차 저장·오류 복구, 수업 상태 변경 중 운행 유지, 결과 저장과 복구를 검증합니다.

`node tests/classroom-browser.mjs` — Playwright가 필요합니다. `PLAYWRIGHT_MODULE`로 설치 경로를 지정할 수 있습니다. 임시 로컬 서버에서 Firebase 대신 탭 간 시연 저장소로 교사·학생 흐름을 검증하며 운영 수업 데이터는 변경하지 않습니다. 1194×834 터치 화면, 코드 입장, 이름표 터치, 운행 중 저장, 안내·성찰 입력 유지, 수업 일시정지·재개, 두 결과 버튼, 재설계 비교, 새로고침, 1024px 교사 단계명을 확인했습니다. 캡처는 `tmp/usability`에 저장됩니다.

`node tests/engine.test.mjs` — 16개 계산 검증을 통과했습니다. 고정 기점, 시간표 연속성, 도로 좌표, 한 대의 물리적 왕복, 이미 출발한 버스, 환승 2분 경계, 저상 제한, 10:00 경계, 도착 시한 경계, 이동 시간 합계와 애니메이션 위치를 검사합니다.

브라우저에서 정류장 추가·삭제·클릭 순서 변경·실제 드래그·되돌리기·첫 출발 변경·저상 배치 변경·운행·일시정지·빠른 보기·시각 탐색·첫 결과 저장·재설계·전후 비교·성찰 작성·새로고침 복구를 직접 확인했습니다.

1586×992 화면을 참고 이미지와 비교했습니다. 1366×768 노트북과 iPad 11인치 가로 기준 1194×834 화면에서 8개 정류장, 편집 도구, 실행 버튼의 가림과 화면 경계를 검사하고 패널을 보완했습니다. 실제 iPad 하드웨어/Safari, 학교 Wi-Fi, 다중 기기 접속은 검증하지 않았습니다. 터치 전용 핵심 조작은 클릭 기반으로 제공하며 마우스와 포인터 드래그를 지원합니다.

WebMCP 설계 읽기·설계 변경 도구의 등록, 유효 입력, 중복 정류장 거부와 상태 보존을 지원 브라우저에서 확인했습니다.

### 계산 검산 예시: 준호

1호차가 07:30에 아파트 → 마을 버스터미널 → 다리 남단 → 공장으로 출발하면 준호는 07:10 집 출발 → 아파트 정류장까지 5분 → 대기 15분 → 07:30 탑승 → 26분 버스 이동 → 공장 정류장 하차 후 4분 이동 → **08:00 도착**입니다. 총 50분이며 도착 시한과 같은 시각이라 정시입니다.
